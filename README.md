# مدرسة النور — النظام المدرسي السحابي 2.0.2

تطبيق مدرسي عربي يعمل كتطبيق ويب تقدمي (PWA) وتطبيق Android عبر WebView. الإصدار 2.0.2 يثبت طبقة API وقاعدة بيانات Neon ومزامنة متعددة الأدوار.

## مكونات السحابة

- PostgreSQL على Neon في منطقة سنغافورة.
- API على Neon Functions باستخدام Node.js 24.
- حساب قاعدة بيانات مخصص `alnoor_school_api` بصلاحيات قراءة وكتابة على مخطط `public`، بدلاً من تشغيل API بحساب مالك قاعدة البيانات.
- جداول الطلاب والحضور والدرجات والواجبات والإعلانات والرسائل والجداول والدروس والتقدم وسجل التدقيق.
- أحداث تغيّر قاعدة البيانات عبر Neon Realtime. يستخدم التطبيق سحباً دورياً كل 20 ثانية كمسار احتياطي عند تعذر WebSocket.
- يحتفظ المتصفح بنسخة محلية من البيانات، ويزامن التعديلات بعد عودة الاتصال.
- حسابات المدرسة تصدرها الإدارة. كلمات المرور تخزن باستخدام PostgreSQL bcrypt/crypt ولا ترجع إلا مرة واحدة عند الإصدار.

## بوابات النظام

- الطالب: الدروس والاختبارات والواجبات ورفع تقدم التعلم والنقاط.
- المعلم: إدارة الدروس والدرجات والحضور والواجبات والجدول ضمن الصف المخصص لحسابه.
- ولي الأمر: متابعة الطالب المرتبط بحسابه والدرجات والحضور والواجبات ورسائل المدرسة.
- المشرف العام: إدارة سجلات المدرسة والحسابات وتهيئة بيانات البداية وتصدير التقرير.

## إعداد أول مدير

1. يفتح مشرف النظام صفحة التهيئة ذات الرمز أحادي الاستخدام التي تصدر بعد نشر الإصدار.
2. تستدعي الصفحة نقطة API خاصة وتصدر كلمة مرور مؤقتة لحساب `ADM-0001`.
3. يسجّل المدير الدخول من بوابة المشرف العام ويغيّر كلمة المرور المؤقتة فوراً.
4. يضغط زر "تهيئة البيانات الافتراضية" لاستيراد بيانات العرض الأولية وإصدار حسابات تجريبية للطالب وولي الأمر والمعلم.
5. يستبدل المدير سجلات العرض ببيانات المدرسة المعتمدة قبل توزيع حسابات فعلية.

لا تضع رمز التهيئة أو كلمات المرور أو اتصال قاعدة البيانات في ملفات GitHub أو في الواجهة.

## البناء والنشر

- GitHub Pages ينشر `index.html`, `sw.js`, `manifest.json` وصفحة تهيئة المدير.
- `.github/workflows/build-neon-function.yml` يجمّع API مع اعتماديات `pg` و`@neon/realtime` في حزمة واحدة قابلة للنشر على Neon Functions.
- `.github/workflows/build-android.yml` يبني APK موقّعاً باستخدام أسرار المستودع:
  - `ANDROID_KEYSTORE_BASE64`
  - `ANDROID_KEYSTORE_PASSWORD`
  - `ANDROID_KEY_ALIAS`
  - `ANDROID_KEY_PASSWORD`
- معرّف التطبيق ثابت: `com.alnoor.school`.
- الإصدار: `versionName 2.0.2`, `versionCode 202`.
- يجب الاحتفاظ بملف JKS نفسه للشهادات الرسمية حتى تبقى التحديثات متوافقة مع النسخ السابقة.

## مساعد نور

يرسل التطبيق السؤال إلى API بعد تسجيل دخول مدرسي. يحتفظ الخادم بمفاتيح Gemini/Groq إن تم ضبطها لاحقاً، ولا يرسلها للمتصفح. عند عدم توفر هذه المفاتيح يحاول الخادم واجهة Pollinations العامة القديمة، ثم يستخدم التطبيق محرك المنهج المحلي عند فشل الاتصال. توفر خدمة خارجية مجانية غير مضمون مدى الحياة؛ لا يوجد ضمان لاستمرار أي واجهة طرف ثالث.

## الأمان والحدود الحالية

- المصادقة المدرسية مستقلة عن وضع المعاينة المحلي، وتستخدم حسابات مرتبطة بدور وسجل طالب أو صف.
- API يتحقق من الدور والصف والطالب المرتبط قبل القراءة أو الكتابة. الطالب لا يملك واجهة لتعديل درجاته أو بيانات سجله؛ يرسل التقدم وإجابات التقييم، ويتحقق الخادم منها ويمنح النقاط مرة واحدة.
- حساب ولي الأمر مقيد بسجل الطالب المرتبط به. حساب المعلم مقيد بالصف المسند إليه.
- Neon Realtime في مرحلة تجريبية، لذلك لا يعتمد التطبيق عليه وحده؛ يوجد سحب دوري بديل.
- قاعدة البيانات الأولية لا تحتوي سجلات طلاب حقيقية. زر التهيئة يستورد بيانات العرض التجريبية من التطبيق فقط.
- قبل اعتماد الاستخدام المدرسي الفعلي، يجب استيراد السجلات المعتمدة، واختبار الأدوار الأربعة على حسابات حقيقية، وضبط النسخ الاحتياطي والاحتفاظ بالبيانات وسياسة الخصوصية، واختبار الاستعادة عند انقطاع الاتصال.
- عدم وضع مفاتيح API أو كلمات المرور داخل مصدر الموقع أو APK أو مستودع GitHub.
- التطبيق لا يضمن توفر Pollinations أو أي مزود ذكاء اصطناعي خارجي بشكل دائم أو مجاني بلا حدود.
